# Audit reference — AI-Powered Bar Management System

> Generated by field-kit 0.1.0 on 2026-11-15. Owned by Field — protected file (`agent-boundaries.md`). Read only by audit sessions (and by planners when a brief carries a hard flag).

The audit is a checklist, not an opinion. Every row of the audit report has an ID and a reference; the auditor answers each row with evidence.

## 1. What can block

A finding is `Must fix` **only when it cites a reference**: an AC of the brief · a rule ID (`core.md`, stack rule file) · a flag-checklist ID below · a `ui.md` row · a brief section (Scope, Read list, §9 Guard).

Everything else goes to **Outside the checklist** in the report and never blocks by itself:
- `taste` — the brief and the rules do not specify it → a note, nothing more.
- `risk` — the auditor believes it is a real defect but nothing above covers it → Field decides: **fix now** (it becomes a `Must fix` citing Field's decision) · **accept** · **add to this file** (the only way these checklists grow).

A brief may add criteria; it can never lower a rule.

## 3. Flag checklists

Answer every item of every flag listed in the brief's `Flags`. Rule IDs in brackets apply when that rule file is installed.

**Concurrency / transaction / idempotency**
- **TX-1** The same request arriving twice at the same time: what stops the second write (unique index, lock, idempotency key)? [NEST-45, NEST-52]
- **TX-2** Every read-then-write (check → update, token rotation, counter, status change) is atomic — one statement, a lock or a constraint, not two separate queries.
- **TX-3** After a caught constraint error the same transaction is not used again. [NEST-55]
- **TX-4** No external call inside a database transaction. [NEST-55]
- **TX-5** Retrying the same request returns the same result and creates nothing twice. [NEST-45]
- **TX-6** Code moved into or out of a transaction, or a shared repository changed: its callers were re-tested (handoff *Callers affected*).

**Money / auth / personal data**
- **SEC-1** Every new or changed route checks on the server who is calling and whether they may act on this record.
- **SEC-2** An ID sent by the client is never trusted for ownership — the record is loaded scoped to the caller.
- **SEC-3** Token / session changes (rotate, revoke, logout) are atomic, and the old one stops working.
- **SEC-4** Money is computed on the server from stored prices; a price already charged never changes.
- **SEC-5** No secret, token or personal data in logs, error bodies, test fixtures or the repo.
- **SEC-6** Cross-origin and socket access is limited to known origins.

**External integration**
- **INT-1** Every outbound call has a timeout and a handled failure path: what the user sees and what state is left behind.
- **INT-2** Incoming callbacks / webhooks: source verified; a duplicate delivery is harmless.
- **INT-3** Vendor errors are translated, never passed raw to the client. [NEST-14, NEST-32]
- **INT-4** Queues, jobs and caches are bounded: retry limit, expiry, or removal on completion.
- **INT-5** The call sits outside database transactions. [NEST-55]

**Migration touching existing rows**
- **MIG-1** Additive, with a working `down`; a merged migration is never edited. [NEST-54]
- **MIG-2** Existing rows get a valid value (backfill or default) — no new required column without one.
- **MIG-3** The code that is live while the migration runs still works (deploy order).
- **MIG-4** Type or precision changes lose no data (timestamps, decimals, text length).

## 4. Re-audit

A re-audit covers the fixed findings (each proven by its reproduce-then-pass evidence) and the diff of the fix commits, against the same rows. Code that passed the first round is not re-opened; something new seen there is an *Outside the checklist* `risk` row.
